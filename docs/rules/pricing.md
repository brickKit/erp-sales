# 单价、金额、税额与汇率

订单与报价的每个数怎样来。所有数都是十进制（契约里是字符串，库里是 `NUMERIC`），舍入只经 SDK 的 `money`（协议 14）。测试按本页的表写。

## 单价

按顺序取第一个成立的（`lines.go` 的 `buildLines`、`pricing.go` 的 `priceOf`）：

| 顺序 | 情形 | 单价 |
| --- | --- | --- |
| 1 | 明细带了单价（人录入，或人改了价格表给出的单价） | 用它，记 `price_source = manual` |
| 2 | 整份替换明细时，被替换的明细里有同一产品、同一销售单位的行 | 沿用它的单价、来源与价格表项（改订单不悄悄换价） |
| 3 | 价格表有（法人、币种、产品、销售单位）在订单业务日期有效的价格 | 取它（不含税），记 `price_source = price_list` 与价格表项的身份；只看启用的价格表，几张同时命中时取起始日期最晚的，再按价格表代码 |
| 4 | 价格表只有该产品基本单位的价格 | 单价 = 基本单位价格 × 换算系数（`mdm/product` 的换算），按单价精度（6 位）舍入 |
| 5 | 都没有 | 拒绝这条明细（`NO_PRICE`，409），由人录入单价后重提 |

销售单位换算不到基本单位时，在取价之前就拒绝（`NO_CONVERSION`，409）。

单价在明细建立或修改时取定，之后价格表变化不影响已有明细；确认时不重新取价。定价规则（折扣、阶梯价、客户价）是替换点，以后加在“取价格表”之后。

## 数量与单位

- 明细的数量用销售单位（可以是包装单位）；`base_quantity` = 经 `mdm/product` 换算成基本单位的数量，按基本单位的小数位舍入。库存的预占与出库只用基本单位。
- 数量按销售单位的小数位校验，多出的位数拒绝，不静默舍入。

## 金额

| 量 | 算法 |
| --- | --- |
| 行金额（不含税） | 数量 × 单价，按订单币种的最小单位舍入（缺省四舍五入远离零） |
| 行税额 | 行金额 × 税率，按行舍入（本版声明“按行”，D49）；税率由人录入，记 `tax_source = manual`（`erp/tax` 没有装） |
| 订单合计 | 行金额之和、行税额之和、两者之和；不另行舍入 |
| 信用分支的金额 | 订单含税合计 |

## 汇率

- 订单币种等于法人本位币：没有汇率。
- 不等：确认时（[confirmation.md](../flows/confirmation.md) 的取证一步）取 `mdm/currency` 在订单业务日期的 `spot` 有效汇率，快照汇率、汇率日期与类型；取不到就不确认（原因“没有汇率”）。报价与草稿只显示参考汇率，不保存。
- 账单沿用订单的快照；财务的记账汇率规则不在本组件。

## 可出账金额（按交货）

一行交货 q 之后，金额维的 `billable` 增加：

- 这次交货之后已交货数量等于订单数量：增加到恰好等于行金额（最后一次交货取余数，避免尾差）；
- 否则：增加 `round(行金额 × q / 订单数量)`。

税额不进台账：出账组件按账单行的金额与订单行的税率自己算税（按行舍入）。
